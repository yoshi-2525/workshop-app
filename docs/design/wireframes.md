# ワイヤーフレーム

最終更新日: 2026-09-28

各画面のレイアウトを ASCII で示す。見出し・ラベル・ボタン文言は JSX の記述をそのまま反映している。共通レイアウト（`Layout` / `Navbar`）は最初に 1 回だけ描き、各画面ではメイン領域（`<main>`）のみを描く。

## 0. 共通レイアウト（Layout / Navbar）

```
┌────────────────────────────────────────────────────────────────────────┐
│ Workshop App                    ワークショップ一覧  (通知)(3)  (人)       │ ← ログイン時
├────────────────────────────────────────────────────────────────────────┤
│ Workshop App            ワークショップ一覧            [ログイン] [新規登録]  │ ← 未ログイン時
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   <main>（最大幅 5xl・中央寄せ）                                         │
│     各画面のメイン領域がここに入る                                       │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

- 通知アイコン・プロフィールアイコンはログイン時のみ、「ログイン」「新規登録」は未ログイン時のみ表示。ログアウトとお気に入りはナビバーには置かず、設定画面（`/settings`）から行う。
- アイコンは Google の Material Symbols（Outlined）の `notifications`（通知）と `account_circle`（プロフィール）。フォントは `frontend/index.html` で Google Fonts から、使うアイコンだけを `icon_names` で指定して読み込む（表示は `frontend/src/components/MaterialIcon.tsx`）。
- 通知アイコンの右上に未読件数バッジ（赤丸）を表示。未読 0 件なら非表示、10 件以上は「9+」。未読件数は 60 秒ごとにポーリングで更新（`frontend/src/context/NotificationContext.tsx:14, 32-37`）。
- プロフィールアイコンは設定画面（`/settings`）へのリンク。名前は画面には出さず、読み上げとマウスを乗せたときの表示（「{name}さんの設定」）で示す。
- 根拠: `frontend/src/components/Layout.tsx`、`frontend/src/components/Navbar.tsx`

### 共通部品: ワークショップカード（WorkshopCard）

一覧・お気に入り・主催者プロフィールで使用。カード全体が詳細画面へのリンク。

```
┌──────────────────────────────────────┐
│ ┌──────────────────────────────────┐ │
│ │            （画像）              │ │
│ └──────────────────────────────────┘ │
│ タイトル                 [予約済み] ♡ │
│ 主催: 主催者名                        │
│ 説明文（2 行で省略）……                │
│ 日時:   2026/10/01 10:00              │
│ 場所:   [会場] 東京都渋谷区…          │
│ 参加費: ¥3,000                        │
│ 定員:   5 / 10                        │
└──────────────────────────────────────┘
```

- 画像は `image_url` がある場合のみ。16:9 の枠に表示し、比率が異なる画像は中央を基準に切り抜く。読み込み失敗時は非表示。
- 「予約済み」バッジは `viewer.is_reserved` のとき表示。
- ♡ はお気に入りボタン（`FavoriteButton`）。ログイン時のみ表示し、未ログインでは表示しない。登録済みは塗りつぶし（赤）。登録・解除に失敗すると `alert()` でエラー（既定「お気に入りの更新に失敗しました」）を表示（`frontend/src/components/FavoriteButton.tsx`）。
- 場所の前に開催形式バッジ（`LocationTypeBadge`: 「オンライン」または「会場」）。
- 参加費は 0 円なら「無料」（緑字）、それ以外は「¥n,nnn」。
- 定員が埋まっていれば「5 / 5(満員)」を赤字で表示。
- 根拠: `frontend/src/components/WorkshopCard.tsx`、`frontend/src/components/LocationTypeBadge.tsx`、`frontend/src/utils/workshop.ts`、`frontend/src/utils/format.ts`

## 1. ワークショップ一覧（`/`）

```
開催予定のワークショップ

┌──────────────────────────────────────────────────────────────────┐
│ キーワードで検索                                                  │
│ [例: 哲学、対話 など(タイトル・詳細から検索)          ]           │
│                                                                  │
│ 開催形式                          料金                            │
│ [すべて|オフライン(会場)|オンライン]  [すべて|無料|有料]            │
│                                                                  │
│ 上限金額(円)                                              [検索] │
│ [指定なし ]   ← 料金「有料」選択時のみ                            │
└──────────────────────────────────────────────────────────────────┘

┌──────────────────────┐  ┌──────────────────────┐
│ ワークショップカード   │  │ ワークショップカード   │
└──────────────────────┘  └──────────────────────┘
┌──────────────────────┐  ┌──────────────────────┐
│ ワークショップカード   │  │ ワークショップカード   │
└──────────────────────┘  └──────────────────────┘
```

- 検索条件は「検索」ボタン押下時に確定し、そのときだけ API を再取得する。取得中は「検索」ボタンが無効。
- キーワードは最大 100 文字。上限金額は 0〜100,000 の整数以外なら「上限金額は 0〜100,000 の整数で入力してください」を入力欄の下に表示し、検索しない。
- 料金で「有料」以外を選ぶと上限金額の入力値とエラーはクリアされる。
- 読み込み中: 「読み込み中...」。
- 0 件: 条件指定ありなら「条件に一致するワークショップはありません。」、なしなら「現在公開中のワークショップはありません。」。
- エラー: API エラーメッセージ（既定「ワークショップの取得に失敗しました」）を赤字で表示。
- カードは 1 列（スマホ）/ 2 列（`sm` 以上）のグリッド。
- 確定した検索条件・参加可能フィルター・並び替え・ページ番号は URL のクエリに持つ（例: `/?q=哲学&date=range&from=2026-10-01&available=1&sort=price&page=2`。既定値の項目は出さない）。ブラウザの「戻る」や再読み込みでも同じ一覧を表示し、入力欄も URL の条件に合わせる。不正な値は無視して既定値に戻す（`frontend/src/utils/workshopListState.ts`）。
- 表示中の一覧 URL とスクロール位置（URL ごと）を sessionStorage に保存する。詳細ページの「ワークショップ一覧に戻る」とブラウザの「戻る」では、一覧を読み込み終えてから保存した位置へスクロールする。ナビバーなどから開いたときは先頭から表示する（ページ移動時の先頭への移動は `frontend/src/components/ScrollToTop.tsx`）。
- 根拠: `frontend/src/pages/WorkshopListPage.tsx`

## 2. ワークショップ詳細（`/workshops/:id`）

```
┌──────────────────────────────────────────────┐
│                 （画像）                      │
└──────────────────────────────────────────────┘
┌──────────────────────────────────────────────┐
│ このワークショップは中止になりました。          │ ← 中止時のみ（赤枠）
└──────────────────────────────────────────────┘
タイトル                                         ♡ ← 公開中のみ
主催: 主催者名（リンク）

┌──────────────────────────────────────────────┐
│ 日時    2026/10/01 10:00                      │
│ 場所    [会場] 東京都渋谷区…  地図で見る       │
│ 参加費  ¥3,000 (当日会場にてお支払いください)  │
│ 定員    5 / 10                                │
└──────────────────────────────────────────────┘

説明文（改行を保持）

┌ キャンセルポリシー ───────────────────────────┐
│ 開催3日前までは無料キャンセル可能です…        │
└──────────────────────────────────────────────┘

[予約する(¥3,000)]
このワークショップは予約済みです。内容の確認・キャンセルは
参加予定のワークショップ から行えます。
```

- 読み込み中: 「読み込み中...」のみ。
- `:id` が不正、または取得失敗: エラーメッセージのみ表示（「ワークショップが見つかりませんでした」または API のエラー）。
- 中止（`canceled`）のとき、画像の下に「このワークショップは中止になりました。」の赤いバナーを表示する。中止済みのワークショップは、主催者本人・admin に加え、そのワークショップを予約したことのあるユーザーも閲覧できる（`backend/app/routers/workshops.py:102-110`）。
- ♡（お気に入りボタン）は公開中（`published`）かつログイン時のみ表示。
- 「地図で見る」はオフライン開催時のみ（Google マップを新しいタブで開く）。
- 参加費の「(当日会場にてお支払いください)」は有料時のみ。
- キャンセルポリシー枠は有料かつポリシー入力ありのときのみ。
- 定員が埋まっている場合は「10 / 10(満員)」を赤字表示。
- 予約ボタンは公開中（`published`）のときのみ表示。文言と状態:
  - 満員: 「満員です」（無効）
  - 未ログイン: 「ログインして予約する」
  - 予約済み: 「予約済みです」（無効）＋ 下の案内文（「参加予定のワークショップ」リンク）
  - それ以外: 「予約する(¥n,nnn)」または「予約する(無料)」
- 画像の上に「← ワークショップ一覧に戻る」リンク。最後に見ていた一覧（検索条件・ページ番号つき）へ戻り、スクロール位置も復元する。一覧を開いていなければトップへ。
- 根拠: `frontend/src/pages/WorkshopDetailPage.tsx`

- 公開中でない場合はフォームの代わりに、中止なら「このワークショップは中止になったため予約できません。」、それ以外（下書き）なら「このワークショップは公開されていないため予約できません。」＋「ワークショップ詳細に戻る」リンクのみ表示。この判定は予約済み・満員の判定より先に行う。

- 読み込み中: 「読み込み中...」、`:id` 不正時: 「ワークショップが見つかりませんでした」、取得失敗: エラーメッセージのみ。
- 根拠: `frontend/src/pages/ReservationFormPage.tsx`、`frontend/src/utils/workshop.ts`

```
│   タイトル                                     │
└──────────────────────────────────────────────┘
┌──────────────────────────────────────────────┐
│   [開催前日] 2026/09/19 10:00                 │ ← 既読
│   「タイトル」は明日開催予定です。…             │
│   タイトル                                     │
└──────────────────────────────────────────────┘
```

- 「すべて既読にする」は未読件数が 1 件以上のときのみ表示。
- 種別バッジ: `cancellation` →「中止」（赤）、`reminder` →「開催前日」（青）。
- 通知カードはワークショップ詳細へのリンク。未読の場合はクリック時に既読化する。

## 14. ワークショップ管理（`/manage`）

```
ワークショップ管理                                        [新規作成]
[開催予定|開催履歴]

┌──────────────────────────────────────────────────────────────────┐
│ ┌──┐ タイトル                   [予約状況] [編集]                   │
│ │画│ 2026/10/01 10:00                                              │
│ └──┘ 公開中 ・ ¥3,000 ・ 予約 5 / 10                               │
└──────────────────────────────────────────────────────────────────┘
（下書きの行と、開催履歴タブの行には [削除] も表示）
```

- サムネイルは 16:9。画像がなければ灰色の四角。
- ステータス表示: `draft` →「下書き」、`published` →「公開中」、`canceled` →「中止」。
- 「編集」は開催予定タブの行のみ。開催履歴（終了日時を過ぎたもの）は編集できない。
- 一覧には「中止する」ボタンを置かない。中止は編集画面（`/manage/workshops/:id/edit`）の下部から行う。
- 「削除」は開催履歴タブの行と、開催予定タブの下書きの行のみ。開催予定の公開中・中止の行には出さない（取りやめる場合は編集画面から中止にする）。API も同じ条件で 409（「開催予定のワークショップは削除できません。開催を取りやめる場合は中止にしてください」）を返す。
- 「削除」の確認文言「このワークショップを削除しますか?」。予約数（`reserved_count`）が 1 以上の行では「削除」ボタンが無効になり、ツールチップ「予約者がいるため削除できません。中止をご利用ください」を表示する。API も同じ条件で 409 を返し、そのエラーメッセージは一覧の上部に赤字で表示される。
- 0 件: 「開催予定のワークショップはありません。」/「開催履歴のワークショップはありません。」。
- admin は全主催者のワークショップが表示される（API 側の挙動。`backend/app/routers/workshops.py:55-60`）。
- 根拠: `frontend/src/pages/manage/ManageWorkshopsPage.tsx`

## 15. ワークショップ新規作成 / 編集（`/manage/workshops/new`, `/manage/workshops/:id/edit`）

```
ワークショップを新規作成（編集時: ワークショップを編集）

タイトル
[                                        ]
説明
┌──────────────────────────────────────────┐
│                                          │
└──────────────────────────────────────────┘
画像
[ファイルを選択] 選択されていません
一覧・詳細ページに16:9で表示される画像をアップロードしてください(推奨サイズ: 1280×720 / jpg, png, webp, gif / 5MBまで)。比率が異なる画像は中央を基準に切り抜いて表示されます。
┌──────────────────────────────────────────┐
│           （プレビュー / 現在の画像）       │
└──────────────────────────────────────────┘

開催形式

  └ 押すとカレンダー（DayPicker）を表示      └ 時・分のセレクト（分は 5 分刻み）

```

- 開催形式が「オンライン」の場合、場所欄は「オンライン開催ツール・URL」（プレースホルダー「例: Zoom(お申し込み後にURLをご案内します)」）になり、「地図で確認」は表示されない。
- 「地図で確認」は場所が未入力の間は無効表示。
- 画像: 新しいファイル選択時はプレビュー＋「画像を取り消す」、既存画像があれば「現在の画像」＋「画像を削除する」。非対応形式・5MB 超はエラー表示して選択を取り消す。
- 参加費を 0 にするとキャンセルポリシーの入力値はクリアされる。
- 下書きの自動保存（`frontend/src/pages/manage/useWorkshopDraft.ts`）: 入力が止まって 1 秒後に、入力内容をブラウザの localStorage（キー `workshop_form_draft:{ユーザーID}:{ワークショップID または new}`）に保存する。新規作成・編集の両方が対象。元の状態と同じなら保存せず削除する。画面を開いたときに下書きがあれば「{日時}に自動保存された入力内容があります。復元しますか?(画像は復元されません)」と「復元する」「破棄する」を表示し、選ぶまでは自動保存を止める。保存成功時・キャンセル時・開催済みで編集できない場合は下書きを削除する。ボタンの上に「入力内容をこのブラウザに自動保存しました(HH:MM)」を表示する。
- 必須項目（タイトル・説明・会場名・住所またはオンライン開催ツール・URL・開始日時・終了日時・定員・参加費）のラベルには赤い「必須」の印（`frontend/src/components/RequiredMark.tsx`）を付け、カードの先頭に「必須 の項目は入力が必要です。」と表示する。画像・キャンセルポリシーは任意。
- 入力欄一式は `WorkshopFormFields`（`frontend/src/pages/manage/WorkshopFormFields.tsx`）として切り出し、枠線付きのカードで表示する。エラーメッセージとボタン（キャンセル / 下書きとして保存 / 公開する）はカードの外に置き、カードとの間を広めに空ける。
- 開始・終了日時は `DateTimeField`（`frontend/src/components/DateTimeField.tsx`）。日付はボタンから開くカレンダー（`@daypicker/react`、日本語表示）で選び、時刻は「時」（0〜23）と「分」（5 分刻み: 00, 05, …, 55）の 2 つのセレクトで選ぶ（時だけ選ぶと分は 00 になる。5 分刻みでない既存の値は選択肢に加えてそのまま表示する）。カレンダーは日付を選ぶか、外側クリック・Esc で閉じる。カレンダーは今月より前の月へは移動できず、昨日以前の日付は選べない（今日は選べる）。終了日のカレンダーでは開始日より前の日付も選べない。開始日を選ぶと（時刻の入力前でも）、終了日が未入力・開始日と同じ日付のまま・開始日より前のいずれかなら、終了日を開始日に自動でそろえる（開始日より後の日付を選んでいる場合はそのまま）。狭い画面では開始・終了を縦に並べる。
- 保存時のクライアント側チェック: 必須未入力・範囲外→「未入力または入力範囲外の項目があります。赤枠の項目を確認してください。」、日時不正→「開始日時・終了日時を正しく入力してください。」、終了≦開始→「終了日時は開始日時より後に設定してください。」。
- 保存中は両ボタンが「保存中...」で無効。
- 「キャンセル」は入力変更時に「入力した内容が破棄されますが、よろしいですか?」を確認して `/manage` へ。
- 編集時の読み込み中は「読み込み中...」のみ。編集時に `:id` が不正な場合は、空のフォームとエラー「ワークショップが見つかりませんでした」を表示する。
- 編集画面では、フォームの下に「ワークショップの中止」の枠を表示する（中止済みのものには出さない）。「中止する」は確認（「このワークショップを中止にしますか?予約済みの参加者には中止のお知らせが自動で届きます。」、編集中の変更があれば「(編集中の内容は保存されません)」を追記）後、保存済みの内容のままステータスを `canceled` に更新して `/manage` へ戻る。フォームで編集中の内容は反映しない。
- ステータスを直接選ぶ UI はなく、「下書きとして保存」→`draft`、「公開する」→`published` で保存する。
- 根拠: `frontend/src/pages/manage/WorkshopFormPage.tsx`
