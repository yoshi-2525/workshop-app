各画面のレイアウトを ASCII で示す。見出し・ラベル・ボタン文言は JSX の記述をそのまま反映している。共通レイアウト（`Layout` / `Navbar`）は最初に 1 回だけ描き、各画面ではメイン領域（`<main>`）のみを描く。

## 0. 共通レイアウト（Layout / Navbar）

```
┌────────────────────────────────────────────────────────────────────────┐
│ TAIWA   さがす  対話のルール            [対話を開く] (問)(2) (通知)(3) (人) │ ← ログイン時（対話を開くは主催者・管理者のみ）
├────────────────────────────────────────────────────────────────────────┤
│ TAIWA   さがす  対話のルール                       [ログイン] [新規登録] │ ← 未ログイン時
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   <main>（最大幅 5xl・中央寄せ）                                         │
│     各画面のメイン領域がここに入る                                       │
│                                                                        │
├────────────────────────────────────────────────────────────────────────┤
│ 違和感を、ひとりで抱えないために。   TAIWA について  対話のルール  ヘルプ・規約 │ ← フッター
└────────────────────────────────────────────────────────────────────────┘
```

- 「さがす」（`/`）「対話のルール」（`/rules`）「対話を開く」（`/manage/workshops/new`）は、狭い画面ではそれぞれ `search` / `menu_book` / `add` のアイコンに置き換わる。
- ログイン時の右端は、問い合わせ（`chat`、`/inquiries`）・通知（`notifications`、`/notifications`）・マイページ（`account_circle`、`/me`）のアイコン。問い合わせと通知には未読件数バッジ（赤丸。10 件以上は「9+」）を付ける。マイページのアイコンは読み上げとマウスを乗せたときの表示で「{name}さんのマイページ」と示す。
- 「ログイン」「新規登録」は未ログイン時のみ表示。ログアウトはナビバーには置かず、マイページから行う。
- 根拠: `frontend/src/components/layout/Layout.tsx`、`frontend/src/components/layout/Navbar.tsx`

### 共通部品: ワークショップカード（WorkshopCard）

一覧・お気に入り・主催者プロフィール・フォロー中の主催者で使用。カード全体が詳細画面へのリンク。

```
┌──────────────────────────────────────┐
│ ┌──────────────────────────────────┐ │
│ │            （画像）              │ │
│ └──────────────────────────────────┘ │
│ タイトル                 [予約済み] ♡ │
│ 主催: 主催者名                        │
│ 説明文（2 行で省略）……                │
│ 日時:   2026/10/01 10:00              │
│ 場所:   [会場] 東京都渋谷区…          │
│ 参加費: ¥3,000                        │
│ 定員:   5 / 10                        │
└──────────────────────────────────────┘
```

- 画像は `image_url` がある場合のみ。16:9 の枠に表示し、比率が異なる画像は中央を基準に切り抜く。読み込み失敗時は非表示。
- 「予約済み」バッジは `viewer.is_reserved` のとき表示。
- ♡ はお気に入りボタン（`FavoriteButton`）。ログイン時のみ表示し、未ログインでは表示しない。登録済みは塗りつぶし（赤）。登録・解除に失敗すると `alert()` でエラー（既定「お気に入りの更新に失敗しました」）を表示（`frontend/src/components/FavoriteButton.tsx`）。
- 場所の前に開催形式バッジ（`LocationTypeBadge`: 「オンライン」または「会場」）。
- 参加費は 0 円なら「無料」（緑字）、それ以外は「¥n,nnn」。
- 定員が埋まっていれば「5 / 5(満員)」を赤字で表示。
- 根拠: `frontend/src/components/workshop/WorkshopCard.tsx`、`frontend/src/components/workshop/LocationTypeBadge.tsx`、`frontend/src/utils/workshop.ts`、`frontend/src/utils/format.ts`（カードの描画内容は本更新では再確認していない）

## 1. ワークショップ一覧（`/`）

```
開催予定のワークショップ

┌──────────────────────────────────────────────────────────────────┐
│ キーワードで検索                                                  │
│ [例: 哲学、対話 など(タイトル・詳細から検索)          ]           │
│                                                                  │
│ 開催形式                          料金                            │
│ [すべて|オフライン(会場)|オンライン]  [すべて|無料|有料]            │
│                                                                  │
│ 上限金額(円)                                              [検索] │
│ [指定なし ]   ← 料金「有料」選択時のみ                            │
└──────────────────────────────────────────────────────────────────┘

┌──────────────────────┐  ┌──────────────────────┐
│ ワークショップカード   │  │ ワークショップカード   │
└──────────────────────┘  └──────────────────────┘
┌──────────────────────┐  ┌──────────────────────┐
│ ワークショップカード   │  │ ワークショップカード   │
└──────────────────────┘  └──────────────────────┘
```

- 検索条件は「検索」ボタン押下時に確定し、そのときだけ API を再取得する。取得中は「検索」ボタンが無効。
- キーワードは最大 100 文字。上限金額は 0〜100,000 の整数以外なら「上限金額は 0〜100,000 の整数で入力してください」を入力欄の下に表示し、検索しない。
- 料金で「有料」以外を選ぶと上限金額の入力値とエラーはクリアされる。
- 読み込み中: 「読み込み中...」。
- 0 件: 条件指定ありなら「条件に一致するワークショップはありません。」、なしなら「現在公開中のワークショップはありません。」。
- エラー: API エラーメッセージ（既定「ワークショップの取得に失敗しました」）を赤字で表示。
- カードは 1 列（スマホ）/ 2 列（`sm` 以上）のグリッド。
- 確定した検索条件・参加可能フィルター・並び替え・ページ番号は URL のクエリに持つ（例: `/?q=哲学&date=range&from=2026-10-01&available=1&sort=price&page=2`。既定値の項目は出さない）。ブラウザの「戻る」や再読み込みでも同じ一覧を表示し、入力欄も URL の条件に合わせる。不正な値は無視して既定値に戻す（`frontend/src/utils/workshopListState.ts`）。
- 表示中の一覧 URL とスクロール位置（URL ごと）を sessionStorage に保存する。詳細ページの「ワークショップ一覧に戻る」とブラウザの「戻る」では、一覧を読み込み終えてから保存した位置へスクロールする。ナビバーなどから開いたときは先頭から表示する（ページ移動時の先頭への移動は `frontend/src/components/ScrollToTop.tsx`）。
- 根拠: `frontend/src/pages/WorkshopListPage.tsx`

## 2. ワークショップ詳細（`/workshops/:id`）

```
← ワークショップ一覧に戻る
┌──────────────────────────────────────────────┐
│                 （画像 / 画像なし）            │
│ ┌──────────────────────────────────────────┐ │

│ └──────────────────────────────────────────┘ │
│ タイトル [満員]                     (共有) (♡) │ ← ♡ は公開中のみ
│ 主催者: (画) 主催者名（リンク）  [主催者に問い合わせる] │
│ ┌──────────────────────────────────────────┐ │
│ │ 日時     2026/10/01 10:00〜12:00          │ │
│ │ 予約締切 2026/09/30 10:00 (開始日時の24時間前まで) │ │
│ │ 場所     [会場] 東京都渋谷区…  地図で見る   │ │
│ │ 参加費   ¥3,000 (予約時にカードでお支払いいただきます) │ │
│ │ 定員     10名 [残席僅か]                   │ │
│ └──────────────────────────────────────────┘ │
│ ┌──────────────────────────────────────────┐ │ ← 有料のときのみ
│ │ キャンセルについて                          │ │
│ │ 参加者のご都合によるキャンセルに、キャンセル料は │ │
│ │ かかりません。… キャンセルポリシー（リンク）   │ │
│ └──────────────────────────────────────────┘ │
│ 説明文（改行を保持）                           │
│                                   [予約する] │
│ （予約済み時）このワークショップは予約済みです。内容は │
│   参加予定のワークショップ から確認できます。…   │
└──────────────────────────────────────────────┘
┌ 参加者へのご案内 ─────────────────────────────┐ ← 予約した参加者・主催者のみ
│ 当日の案内 / 緊急連絡先                        │
└──────────────────────────────────────────────┘
（関連するワークショップ）
```

- 読み込み中: 読み込み中の表示のみ。`:id` が不正、または取得失敗: 戻るリンクとエラーメッセージのみ。
- 中止（`canceled`）のとき、画像の下に「このワークショップは中止になりました。」の赤いバナーを表示する。
- 参加費の注記（`paymentNote()`）: 無料なら出さない。有料で支払方法が `online` なら「(予約時にカードでお支払いいただきます)」、`onsite` なら「(当日会場にてお支払いください)」（`frontend/src/utils/payment.ts:46-50`）。
- 「キャンセルについて」（`CancellationPolicy`）: 無料なら出さない。有料なら日時などの欄のすぐ下に、本サービス共通のキャンセルポリシーの要約（`cancellationSummary()`）と、`/help/cancellation-policy` への「キャンセルポリシー」リンクを表示する。ワークショップごとのキャンセルポリシーはない（`frontend/src/components/workshop/CancellationPolicy.tsx`、`frontend/src/utils/payment.ts:97-105`）。
  - 当日払い: 「参加者のご都合によるキャンセルに、キャンセル料はかかりません。キャンセルをご希望の場合は、主催者にご連絡ください。」
  - オンライン決済: 「主催者の都合によるキャンセルと中止は全額を、参加者のご都合によるキャンセル(主催者が受け付けた場合)は決済手数料と本サービスの手数料を差し引いた額を返金します。」
- 「主催者に問い合わせる」は自分のワークショップなら「届いた問い合わせ」（`/inquiries?workshop_id=:id`）になり、下書きでは出さない。
- 予約締切・タイトル横のバッジ（「満員」または「受付終了」）・「残席僅か」は、公開中で開始前のときだけ表示する（`frontend/src/components/workshop/SeatStatusBadge.tsx`）。
- 予約ボタンは公開中（`published`）のときのみ表示。文言と状態（`frontend/src/pages/workshops/WorkshopDetailPage.tsx:41-47, 232-248`）:
  - 開始済み: 「開始済みのため予約できません」（無効）
  - 締切後: 「予約の受付は終了しました」（無効）
  - 満員: 「空席がないため予約できません」（無効）
  - 未ログイン: 「ログインして予約する」
  - オンライン決済の支払い待ち（`viewer.is_payment_pending`）: 「お支払いを再開する」（満員でも押せる）
  - それ以外: 「予約する」
  - 予約済み・主催者による取消済み: ボタンを出さず、案内文（予約済み: 「…キャンセルをご希望の場合は主催者にご連絡ください。」、取消済み: 「主催者により参加がキャンセルされたため、このワークショップは予約できません。」）を表示する。
- 根拠: `frontend/src/pages/workshops/WorkshopDetailPage.tsx`、`frontend/src/components/workshop/CancellationPolicy.tsx`、`frontend/src/utils/payment.ts`、`frontend/src/utils/workshop.ts`

## 3. 主催者プロフィール（`/facilitators/:id`）

```
┌──────────────────────────────────────────────┐
│ ┌──┐ 主催者名                    [フォローする] │
│ │画│ 主催者                                    │
│ └──┘                                          │
│                                              │

┌──────────────────────┐  ┌──────────────────────┐
│ ワークショップカード   │  │ ワークショップカード   │
└──────────────────────┘  └──────────────────────┘
```

- 左上はアバター（`Avatar`。`avatar_url` と名前から表示）。
- ロール表示は admin なら「運営」、それ以外は「主催者」。
- フォローボタン（`FollowButton`）の表示:
  - 相手が admin（運営）のページ、または自分自身のページ: 表示しない。
  - 未ログイン: 「ログインしてフォロー」（副ボタンの見た目のリンク。参加者ログインへ `state.from` 付きで遷移）。
  - フォローしていない: 「フォローする」（主ボタン）。
  - フォロー中: 「フォロー中」（副ボタン、`aria-pressed="true"`）。押すと解除。
  - 処理中はボタンが無効。失敗時はボタンの下に「フォローの更新に失敗しました」等を 4 秒間表示。
  - 初期状態は API の `viewer.is_following`（null なら未フォロー扱い）。
- 自己紹介が空なら「自己紹介はまだ登録されていません。」。
- ワークショップ 0 件: 「開催予定のワークショップはありません。」。
- ワークショップカードには戻るリンク用に「{主催者名}さんのページ」を渡す。
- 読み込み中: 読み込み中の表示（`LoadingMessage`）、`:id` 不正時: 「主催者が見つかりませんでした」、エラー: 「主催者情報の取得に失敗しました」等。
- 根拠: `frontend/src/pages/workshops/FacilitatorProfilePage.tsx`、`frontend/src/components/facilitator/FollowButton.tsx`、`frontend/src/utils/user.ts:18-30`

- 予約できない場合はフォームの代わりにメッセージとリンクのみ表示する（判定順は `getReservationBlocker()`）:

  - 締切後: 「予約の受付は開始日時の24時間前で締め切りました。」
  - 満員: 「このワークショップは満員のため予約できません。」
  - 予約済み以外のリンクは「ワークショップ詳細に戻る」。

- 開始・終了日時は `DateTimeField`（`frontend/src/components/DateTimeField.tsx`）。日付はボタンから開くカレンダー（`@daypicker/react`、日本語表示）で選び、時刻は「時」（0〜23）と「分」（5 分刻み: 00, 05, …, 55）の 2 つのセレクトで選ぶ（時だけ選ぶと分は 00 になる。5 分刻みでない既存の値は選択肢に加えてそのまま表示する）。カレンダーは日付を選ぶか、外側クリック・Esc で閉じる。カレンダーは今月より前の月へは移動できず、昨日以前の日付は選べない（今日は選べる）。終了日のカレンダーでは開始日より前の日付も選べない。開始日を選ぶと（時刻の入力前でも）、終了日が未入力・開始日と同じ日付のまま・開始日より前のいずれかなら、終了日を開始日に自動でそろえる（開始日より後の日付を選んでいる場合はそのまま）。狭い画面では開始・終了を縦に並べる。
- 保存時のクライアント側チェック: 必須未入力・範囲外→「未入力または入力範囲外の項目があります。赤枠の項目を確認してください。」、日時不正→「開始日時・終了日時を正しく入力してください。」、終了≦開始→「終了日時は開始日時より後に設定してください。」。
- 保存中は両ボタンが「保存中...」で無効。
- 「キャンセル」は入力変更時に「入力した内容が破棄されますが、よろしいですか?」を確認して `/manage` へ。
- 編集時の読み込み中は「読み込み中...」のみ。編集時に `:id` が不正な場合は、空のフォームとエラー「ワークショップが見つかりませんでした」を表示する。
- 編集画面では、保存済みのワークショップが公開中のときだけ、フォームの下に「ワークショップの中止」の枠を表示する（下書きは中止できず、一覧から削除する）。「中止する」は確認（「このワークショップを中止にしますか?予約済みの参加者には中止のお知らせが自動で届きます。」。オンライン決済のワークショップでは「オンラインで支払われた参加費は全額を返金します(決済手数料は戻らず、主催者の負担になります)。」、編集中の変更があれば「(編集中の内容は保存されません)」を追記）後、保存済みの内容のままステータスを `canceled` に更新して `/manage` へ戻る。処理中は「処理中...」（`frontend/src/pages/manage/WorkshopFormPage.tsx:159-180, 347-371`）。
- ステータスを直接選ぶ UI はなく、「下書きとして保存」→`draft`、「公開する」→`published` で保存する。
